# 204 节点 Ubuntu 虚拟机与 RKE2 集群搭建流程

## 宿主机与连接方式

操作日期：2026 年 10 月 27 日。

| 项目 | 配置 |
| --- | --- |
| 跳板机 | `10.100.1.91` |
| 虚拟化宿主机 | `10.100.1.94`，主机名称 `204` |

## 虚拟机与网络配置

| 虚拟机 | 角色 | IP 地址 | CPU | 内存 | 系统磁盘 |
| --- | --- | --- | --- | --- | --- |
| `rke2-server-1` | 控制平面、etcd | `192.168.204.11` | 4 vCPU | 4 GiB | 20 GiB |
| `rke2-worker-1` | 工作节点 | `192.168.204.12` | 4 vCPU | 4 GiB | 20 GiB |
| `rke2-worker-2` | 工作节点 | `192.168.204.13` | 4 vCPU | 4 GiB | 20 GiB |
| `rke2-worker-3` | 工作节点 | `192.168.204.14` | 4 vCPU | 4 GiB | 20 GiB |

合计配置 16 vCPU、16 GiB 内存、80 GiB 虚拟磁盘容量。qcow2 按实际写入数据占用宿主机空间。

libvirt 网络名称为 `rke2-lab`，桥接接口为 `virbr-rke2`，网关为 `192.168.204.1/24`。通过 MAC 地址固定 DHCP 分配结果，虚拟机使用 NAT 访问外部网络。宿主机可以直接连接这些地址；校外终端通过跳板机、宿主机进入虚拟机网络。

Pod 地址范围为 `10.244.0.0/16`，Service 地址范围为 `10.245.0.0/16`，集群 DNS 为 `10.245.0.10`。这些地址避开宿主机已有的 Docker 网络、`10.42.0.0/16` Pod 网络和物理接口网络。

四台虚拟机均位于同一宿主机，控制平面使用单个 etcd 成员。宿主机故障将影响整个集群。每台虚拟机的 CPU、内存配置对应节点容量，Pod 通过 Kubernetes 的 requests、limits 分配资源。

## 安装宿主机依赖

在宿主机执行：

```bash
mkdir -p /var/lib/rke2-lab/work
apt-get update
DEBIAN_FRONTEND=noninteractive apt-get install -y \
  qemu-kvm libvirt-daemon-system virtinst cloud-image-utils
systemctl is-active libvirtd
test -c /dev/kvm
```

安装材料位于 `/var/lib/rke2-lab`。虚拟磁盘和 cloud-init 种子磁盘位于 `/var/lib/libvirt/images/rke2-lab`。

## 下载与校验 Ubuntu 镜像

在宿主机执行：

```bash
cd /var/lib/rke2-lab
curl -fL --connect-timeout 15 --max-time 600 \
  https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img \
  -o noble-server-cloudimg-amd64.img
curl -fL --connect-timeout 15 --max-time 60 \
  https://cloud-images.ubuntu.com/noble/current/SHA256SUMS \
  -o work/SHA256SUMS
sha256sum --ignore-missing -c work/SHA256SUMS
```

本次使用的 Ubuntu 镜像 SHA256 为：

```text
04e8f2461a16a44e78a370284471f29616cdd9baf1893df25807b71f985b6c94
```

cloud-init 创建 `ubuntu` 用户，授权部署专用 SSH 公钥，允许该用户执行 sudo，关闭 SSH 密码认证。部署私钥保存在宿主机 `/var/lib/rke2-lab/id_ed25519`，权限为 `0600`。

重新搭建独立环境时，在新安装目录生成部署密钥，然后使用文本编辑器将公钥填写到 `user-data` 的 `ssh_authorized_keys` 中：

```bash
ssh-keygen -t ed25519 -N '' -C rke2-lab-204 \
  -f /var/lib/rke2-lab/id_ed25519
cat /var/lib/rke2-lab/id_ed25519.pub
```

当前环境使用已经部署的密钥，保留该私钥即可继续管理现有虚拟机。交付配置材料包含公钥和安装脚本，私钥保留在受控安装目录中。

## 创建虚拟机

检查提供的 `network.xml`、`user-data` 和四份 `meta-data`，然后在宿主机执行：

```bash
cd /var/lib/rke2-lab
bash provision.sh
virsh list --all
virsh net-dhcp-leases rke2-lab
```

`provision.sh` 定义 NAT 网络，为四个不同的 MAC 地址分配固定 IP，分别创建 20 GiB qcow2 磁盘，并使用 virtio 磁盘和网卡启动虚拟机。网络和虚拟机均配置自动启动。创建脚本要求名称和目录尚未存在。

## 准备 RKE2 离线安装材料

在能够访问 GitHub 的机器下载同一版本的三个官方文件：

```bash
curl -fL 'https://github.com/rancher/rke2/releases/download/v1.36.5%2Brke2r1/rke2.linux-amd64.tar.gz' \
  -o rke2.linux-amd64.tar.gz
curl -fL 'https://github.com/rancher/rke2/releases/download/v1.36.5%2Brke2r1/rke2-images.linux-amd64.tar.zst' \
  -o rke2-images.linux-amd64.tar.zst
curl -fL 'https://github.com/rancher/rke2/releases/download/v1.36.5%2Brke2r1/sha256sum-amd64.txt' \
  -o sha256sum-amd64.txt
sha256sum --ignore-missing -c sha256sum-amd64.txt
```

将两个归档文件放入宿主机 `/var/lib/rke2-lab/work`，校验文件放入 `/var/lib/rke2-lab`。从 `https://get.rke2.io` 下载官方安装脚本至 `work/install-rke2.sh`。离线镜像由安装脚本校验并复制到各节点的 `/var/lib/rancher/rke2/agent/images`。

```bash
curl -fL https://get.rke2.io \
  -o /var/lib/rke2-lab/work/install-rke2.sh
```

## 安装控制平面和工作节点

在宿主机执行：

```bash
cd /var/lib/rke2-lab
chmod 600 id_ed25519
bash install-cluster.sh
```

脚本等待 cloud-init 完成，安装 AppArmor、iptables、curl、CA 证书及 NFS 客户端，检查 swap 和时间同步，再分发离线安装材料。

控制平面使用提供的 `server.yaml`，安装后保存到 `/etc/rancher/rke2/config.yaml`。配置明确指定节点地址、Pod 和 Service 网段、Canal、Traefik，并设置控制平面 `NoSchedule` 污点。管理员 kubeconfig 权限为 `0600`。

工作节点使用提供的 `agent.yaml`，通过 `https://192.168.204.11:9345` 注册。加入令牌经 SSH 传输，安装到工作节点 `/etc/rancher/rke2/node-token`，权限为 `0600`。

服务名称分别为 `rke2-server`、`rke2-agent`。节点之间允许 Kubernetes API `6443/TCP`、注册端口 `9345/TCP`、kubelet `10250/TCP` 和 Canal VXLAN `8472/UDP` 通信。

## 连接虚拟机并管理 Kubernetes

在宿主机执行：

```bash
ssh -i /var/lib/rke2-lab/id_ed25519 ubuntu@192.168.204.11
sudo /var/lib/rancher/rke2/bin/kubectl \
  --kubeconfig /etc/rancher/rke2/rke2.yaml get nodes -o wide
```

进入控制平面管理员 shell 后设置环境变量：

```bash
sudo -i
export TERM=xterm-256color
export PATH=/var/lib/rancher/rke2/bin:$PATH
export KUBECONFIG=/etc/rancher/rke2/rke2.yaml
kubectl get nodes -o wide
kubectl get pods -A
```

## 验收项目

使用 `validation.yaml` 在三个工作节点部署 BusyBox HTTP 服务，通过 `validate-cluster.sh` 检查 API、节点就绪状态、DNS、Service 和跨节点 Pod 通信，并创建 etcd 快照。验证镜像为 `busybox:1.37.0`，通过 Docker 下载 amd64 镜像后导出，再使用各节点的 containerd 导入。

在可访问 Docker Hub 且运行 Docker 的机器执行：

```bash
docker pull --platform linux/amd64 busybox:1.37.0
docker save --platform linux/amd64 -o busybox-1.37.0.tar busybox:1.37.0
```

将归档传入宿主机 `/var/lib/rke2-lab/work`。`deploy.sh` 包含安装和验证镜像分发步骤，可以作为完整安装入口：

```bash
cd /var/lib/rke2-lab
bash deploy.sh
```

安装和验收分别记录在 `work/deploy.log`、`work/acceptance.log`。在已经完成安装的环境中，可以单独执行镜像导入和验收，无需再次执行安装流程。单台节点的镜像导入命令为：

```bash
scp -i /var/lib/rke2-lab/id_ed25519 work/busybox-1.37.0.tar \
  ubuntu@192.168.204.12:/home/ubuntu/
ssh -i /var/lib/rke2-lab/id_ed25519 ubuntu@192.168.204.12 \
  sudo /var/lib/rancher/rke2/bin/ctr \
  --address /run/k3s/containerd/containerd.sock --namespace k8s.io \
  images import /home/ubuntu/busybox-1.37.0.tar
```

控制平面执行：

```bash
sudo bash /home/ubuntu/validate-cluster.sh
```

## 日常维护

在宿主机查看虚拟机：

```bash
virsh list --all
virsh dominfo rke2-server-1
virsh net-dhcp-leases rke2-lab
df -h /
```

在控制平面检查服务、资源和备份：

```bash
systemctl status rke2-server
journalctl -u rke2-server -n 100 --no-pager
kubectl get nodes -o wide
kubectl get pods -A
kubectl top nodes
RKE2_CONFIG_FILE=/dev/null rke2 etcd-snapshot save --name manual
RKE2_CONFIG_FILE=/dev/null rke2 etcd-snapshot ls
```

etcd 默认每 12 小时创建本地快照，保留 5 份。快照目录为 `/var/lib/rancher/rke2/server/db/snapshots`。恢复时需要同时保留服务器令牌；完整数据备份还需要包含业务 PVC 或其他持久数据。20 GiB 系统磁盘用于当前集群组件和验证工作负载，运行业务时需要检查磁盘使用情况。
